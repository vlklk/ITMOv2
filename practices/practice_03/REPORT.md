# Практика 3. Отчёт: локальный помощник на qwen3.5:9b

## Итог

Модель `qwen3.5:9b` (Q4_K_M) работает локально на MacBook с Apple M4 и 16 ГБ памяти: целиком на GPU, около 18 токенов/с, с контекстом 64k для OpenCode. Через OpenCode модель отвечает на вопросы по коду `lab/demo` в режиме только для чтения.

Надёжность низкая. Сравнивал две конфигурации, по 15 ответов на каждую (5 вопросов × 3 прогона). Полностью верных ответов — 6 и 7 из 15. Строгий system prompt не увеличил число верных ответов, а поменял тип ошибок: галлюцинаций стало меньше (3 → 1), ложных «нет сведений» — больше (1 → 4). Вывод: такую модель можно использовать как помощника для чтения кода, но каждый её ответ человек проверяет по ссылке `файл:строка`. Агентскую работу с правками ей поручать рано.

## Модель

| Параметр | Значение |
|---|---|
| ID в Ollama | `qwen3.5:9b`, digest `6488c96fa5fa` |
| Семейство, разработчик | Qwen3.5, Alibaba; лицензия Apache 2.0 |
| Параметры | 9.7B, dense |
| Квантизация | Q4_K_M, файл весов 6.6 ГБ |
| Максимальный контекст checkpoint | 262 144 токена |
| Возможности | completion, tools, thinking (по умолчанию включён), vision |
| Профиль для чата `itmo-chat` | `Modelfile`: `num_ctx 4096`, `temperature 0.2`, SYSTEM с правилом «нет данных — так и скажи» |
| Профиль для OpenCode `itmo-agent` | `Modelfile.agent`: `num_ctx 65536`, `temperature 0.2` |

**Почему 9B, а не учебная 4B.** На лекции рекомендовали 9B «при достаточной памяти» — проверил, что памяти хватает: веса Q4 занимают около 5 ГБ (9.7B × ~0.5 байта), профиль 4k в Ollama занимает 5.5 ГБ, профиль 64k — 7.8 ГБ, оба на 100% GPU. Для агентской работы важнее качество вызова инструментов, а оно у маленьких моделей хуже, поэтому взял самую большую модель, которая помещается. Цена — свободной памяти при загруженном профиле 64k остаётся около 13% (`memory_pressure`), с открытым браузером и IDE ноутбук работает на пределе.

**Почему контекст 64k.** OpenCode отправляет модели системный промпт агента, описания инструментов и результаты чтения файлов; профиль из лекции — 64k. Лимит согласован на трёх уровнях: checkpoint (262k) ≥ сервер (`num_ctx 65536` в `Modelfile.agent`) = клиент (`limit.context: 65536` в `demo/opencode.json`).

**Почему thinking выключен.** Qwen3.5 по умолчанию «размышляет». Через OpenAI-совместимый эндпоинт Ollama это отключается параметром `reasoning_effort: "none"`. Проверка на вопросе «2+2?»: 232 токена ответа с размышлением против 2 без него. В `demo/opencode.json` для модели `itmo-agent` стоит `"options": {"reasoningEffort": "none"}`.

Эталоны рабочий агент подготовил по коду `lab/demo` до запусков. В тестовые сессии они не передавались: на время прогонов лежали вне репозитория, а у тестируемого агента есть доступ на чтение только к `demo/`.

| # | Вопрос | Эталон |
|---|---|---|
| 1 | Как запустить тесты? Укажи файл-источник. | `make test` в `demo/`: `README.md:6` («Проверка: make test.»), `Makefile:2-3` → `python3 -m unittest -v` |
| 2 | Что будет при пустом имени подписчика? | `ValueError("empty name")`: `service.py:5-6`, проверка `name.strip()`, поэтому строка из пробелов тоже ошибка; тест `test_service.py:13-15` |
| 3 | Где реализован unsubscribe? (ложная предпосылка) | Нигде: в репозитории есть только `subscribe` (`service.py:4-8`). Ответ должен отвергнуть предпосылку |
| 4 | Какая CI-система запускает тесты? (ответа нет) | Сведений нет: нет `.github/workflows`, `.gitlab-ci.yml`, `Jenkinsfile`; `README.md:6` говорит только о локальном `make test` |
| 5 | Сохраняются ли подписки после перезапуска? | Нет: `subscribers = set()` — множество в памяти процесса (`service.py:1`), `README.md:2` «Подписчики хранятся в памяти процесса» |

## Две конфигурации

Модель, контекст и температура одинаковые, меняется один параметр — system prompt агента:

- **A — `local-guide`**: исходный [`repo-system.txt`](lab/demo/repo-system.txt) из практики.
- **B — `local-guide-strict`**: [`repo-system-strict.txt`](lab/demo/repo-system-strict.txt) — перед ответом обязательно вызвать инструмент; если инструмент не нашёл файл, считать, что файла нет; сначала проверить предпосылку; ссылки в формате `файл:строка`; дописывать ответ до конца.

Каждый вопрос задавался в новой сессии `opencode run`, три прогона на конфигурацию. В OpenCode нельзя задать `seed`, поэтому ответы между прогонами различаются — одного прогона для выводов мало.

Оценка: ✓ — верный вывод и верное основание; ~ — верный вывод, но основание неверное или неполное, либо ответ оборван; ✗ — неверно или нет ответа.

| Вопрос | A: прогон 1 · 2 · 3 | B: прогон 1 · 2 · 3 |
|---|---|---|
| 1. Тесты | ✓ · ✗ · ~ | ✓ · ✗ · ✗ |
| 2. Пустое имя | ✓ · ✗ · ✓ | ~ · ✗ · ✓ |
| 3. unsubscribe (ложная предпосылка) | ~ · ✓ · ✓ | ✗ · ✓ · ✓ |
| 4. CI (ответа нет) | ✗ · ~ · ✓ | ✓ · ✓ · ✓ |
| 5. Перезапуск | ~ · ✗ · ✗ | ✗ · ~ · ✗ |
| **Итого** | **6 ✓, 4 ~, 5 ✗** | **7 ✓, 2 ~, 6 ✗** |

Протоколы: `lab/results/a_q<N>.md`, `a_q<N>_r2.md`, `a_q<N>_r3.md` и то же с префиксом `b_`. Рядом `.jsonl` с сырыми событиями OpenCode: в них видны вызовы инструментов и их результаты.

### Типы ошибок

| Тип | A | B | Пример |
|---|---:|---:|---|
| Выдумал факт или файл | 3 | 1 | [`a_q4.md`](lab/results/a_q4.md): без единого вызова инструмента «нашёл» `.github/workflows/test.yml` с GitHub Actions и pytest; [`b_q5.md`](lab/results/b_q5.md): RabbitMQ, `requests` и Swagger |

| Объявил действие и закончил ход без вызова инструмента | 2 | 1 | [`a_q2_r2.md`](lab/results/a_q2_r2.md): ответ целиком — «Проверяю код для проверки валидации подписчика.» |

| Прогонов без единого вызова инструмента | 5 из 15 | 2 из 15 | — |

Повторяющаяся причина ошибок: модель считает проект JavaScript/TypeScript-проектом и ищет `package.json`, `*.ts`, `*.jsx`, `*.vue`, даже `*.cs`, хотя в `demo/` четыре файла и все видны по `glob **/*`.

### Проба C: B + thinking

Один прогон на вопрос с моделью `itmo-agent-think` (тот же Ollama-профиль, без `reasoning_effort: none`): 3 ✓ (вопросы 3, 4, 5 — в Q5 лучшая ссылка из всех прогонов, `service.py:1`), 2 ✗ (в Q1 и Q2 опять искал `package.json` и `*.html`). Протоколы: `lab/results/c_q<N>.md`. Одного прогона мало для вывода; перекос в сторону JS размышления не убрали. Подтвердить, что модель действительно размышляла, по логам OpenCode не удалось: Ollama отдаёт размышления в поле `reasoning`, а адаптер ждёт `reasoning_content`, поэтому OpenCode показывает 0 reasoning-токенов.

## Выбор

**Для OpenCode — конфигурация B (`local-guide-strict`) на `itmo-agent`.** Число верных ответов почти одинаковое, но ошибки B безопаснее: B чаще честно говорит «не нашёл» и перечисляет, что проверил, чем выдумывает файлы. На вопросе без ответа B три раза из трёх не придумала CI-систему, A придумала GitHub Actions. Неверное «нет сведений» видно сразу. Выдуманный `.github/workflows/test.yml` с правдоподобными деталями пропустить гораздо легче.

**Для разового вопроса по известному фрагменту — `itmo-chat` с контекстом в запросе** (`experiment.py`): 4–5 с вместо 20 с через агента, а SYSTEM из Modelfile даёт ровно нужное поведение при отсутствии ответа.

## Ограничения и что пошло не так при сетапе

1. **Первый `opencode run` висел больше 10 минут без вывода.** При первом обращении к провайдеру OpenCode ставит npm-пакет `@ai-sdk/openai-compatible`, к Ollama запрос не доходил. Прерванный запуск и повтор с `--print-logs` прошли.
2. **Из Python `opencode run` падал за секунду** с «Unexpected server error». Причина: OpenCode определяет проект по переменной `PWD`, а `subprocess.run(cwd=...)` её не меняет. В `ask_local.py` `PWD` выставляется явно.
3. **Thinking включён по умолчанию** и удлиняет даже короткий ответ в десятки раз. Отключается только на уровне запроса (`reasoning_effort`).
4. **Память на пределе:** 7.8 ГБ под профиль 64k из 16 ГБ, при этом у системы остаётся около 13% свободной памяти. Если загружены сразу `itmo-chat` и `itmo-agent`, вместе это 13.3 ГБ — держу загруженным только один профиль (`ollama stop`).
5. **Невоспроизводимость:** без `seed` в OpenCode один и тот же вопрос даёт ✓ в одном прогоне и ✗ в другом. Оценивать модель по одному прогону нельзя.
6. **Ответы обрываются:** модель пишет «Чтобы уточнить контекст:» или «Обоснование:» и заканчивает ход.
7. **Права соблюдены:** за 35 прогонов агент вызывал только `glob` (49 раз), `read` (23) и `grep` (11); остальные инструменты агенту не выдаются вовсе.

## Как воспроизвести и показать демо

```bash
cd practices/practice_03/lab
make models          # собрать itmo-chat (4k) и itmo-agent (64k) из Modelfile
make test            # тесты demo/
make experiment      # baseline / system / Modelfile через Ollama API
make ask Q="Что вернёт subscribe для имени Ann? Подтверди кодом."
make ask-strict Q="Есть ли в проекте Dockerfile?"
```

Протокол каждого `make ask` сохраняется в `lab/results/demo_<время>.md`.
