# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md) — нагрузочные проверки сервиса code review
- Что хотим улучшить: в исходной версии две строки таблицы и заглушка «нагрузочное тестирование станет актуальным позже». Нужен формат строки, из которого видно нагрузку, числовой предел, измеряемую метрику и артефакт-подтверждение

## Примеры

### Хороший результат

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Подтверждение |
|---|---|---|---|---|
| **Baseline** — последовательные запросы | 10 rps × 60 с, diff ~5 000 символов | p95 ≤ 8 с, p99 ≤ 10 с, 0 ошибок 5xx | p95/p99, доля успешных ответов, пропускная способность | `k6/scenarios/baseline.js`, `k6/results/baseline.json` |

### Плохой результат

| Сценарий | Нагрузка и длительность |
|---|---|
| Обычный поток | 10 запросов в секунду |

Нагрузочное тестирование пока не требуется.

## Запрос

Напиши нагрузочные проверки для FastAPI-сервиса code review. Инструмент k6, скрипты в `tests/load/`. Правила: SEC-1 — очистка секретов, API-1 — diff > 20k → HTTP 413, REL-1 — timeout LLM 10 сек, OUT-1 — формат ответа (summary, risks, checks), OBS-1 — лог только request_id, duration, status. 4–5 сценариев: baseline, spike, soak, ramp-up, stress. Каждый сценарий — с конфигурацией k6. Таблица интерпретации метрик. Инструкция по запуску. Подтверждение со ссылками на строки кода и на правила. Следуй формату хорошего примера выше: пять колонок, числовой предел и артефакт в каждой строке. Плохой пример — строка без предела и без артефакта.

## Что получили

- 5 сценариев в формате хорошего примера: каждая строка содержит нагрузку, числовой предел, измеряемую метрику и артефакт
- Конфигурации k6 с thresholds, дублирующими колонку «Допустимый предел»
- Таблица интерпретации: Acceptable / Warning / Failure
- Раздел «Что нельзя тестировать сейчас» с обоснованием, почему REL-1 и OBS-1 ещё не измеримы
- Ссылки на `app/review_service.py:20-21`, `app/api.py:36-37` и на правила REL-1, API-1 из Context Pack

## Что изменили в исходном артефакте

- Файл и раздел: [`../../practice_01/tests_load.md`](../../practice_01/tests_load.md), раздел «Матрица сценариев», уровень L1 (сценарии L1-1 … L1-5)
- Изменение: задан формат строки матрицы — пять колонок, числовой предел и артефакт-подтверждение в каждой строке. Пять сценариев уровня L1 перенесены в файл в этом формате; строки старой таблицы без артефактов удалены. Черновик ответа отдельным файлом не сохраняли: согласованная часть перенесена в артефакт Практики 1
- Как проверили: `make step1` из корня репозитория (файл непустой, структура на месте); вручную сверили, что ни одна строка матрицы не осталась без числового предела и без артефакта, а пороги совпадают с REL-1 (≤ 10 с) и API-1 (HTTP 413)
- Что отклонили: вариант с одним сценарием baseline + spike — не покрывает soak и поиск точки насыщения; порог 500 мс вместо 8/10 с — несовместим с сервисом, который синхронно ждёт внешний LLM с timeout 10 с; строки в формате плохого примера (нагрузка без предела)
