# Style guide

1. Поведение проверяем через публичный интерфейс: HTTP-запросы `TestClient`, а не приватные функции.
2. Каждое правило из `docs/requirements.md` — отдельный тест с ID правила в имени (`test_api1_...`, `test_rel1_...`).
3. Ошибки отдаём через `HTTPException` с коротким `detail` на английском; внутренние сообщения наружу не выходят.
4. Не добавляем новые зависимости и фреймворки ради маленькой правки.
5. Не ослабляем `scripts/check.sh` и не удаляем тесты ради зелёного результата.

Хороший пример — `tests/test_api.py::test_review_returns_llm_answer`: запрос через HTTP, проверка кода ответа, тела и числа вызовов LLM.
