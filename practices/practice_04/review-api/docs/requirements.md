# Контракт сервиса AI-review

Источник правил — Context Pack Практики 1 (`practices/practice_01/context.md`, ветка `practice_01`).

## Эндпоинт

`POST /api/reviews` принимает JSON `{"diff": "<unified diff>"}` и возвращает результат ревью от LLM.
`GET /health` возвращает `{"status": "ok"}`.

## Правила

| ID | Правило |
|---|---|
| SEC-1 | Перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. |
| API-1 | diff длиннее 20 000 символов отклоняется с HTTP 413. |
| REL-1 | Внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. |
| OUT-1 | Ответ ревью содержит `summary`, массив `risks` (≤ 3, поля `file`, `line`, `evidence`, `risk`) и массив `checks`. |
| SCOPE-1 | Сервис только советует: не пишет код и не выполняет действия в GitHub. |
| QA-1 | Риск включается в ответ, только если подтверждён строкой diff или правилом. |
| OBS-1 | В лог пишутся только `request_id`, длительность и статус; diff и ответ модели не логируются. |

## Фича A — входная валидация (API-1)

1. Нет поля `diff` или оно не строка → HTTP 422, LLM не вызывается.
2. Пустой diff (после `strip()`) → HTTP 422, LLM не вызывается.
3. Длина diff больше 20 000 символов → HTTP 413 с телом `{"detail": "diff too large"}`, LLM не вызывается.
4. Ровно 20 000 символов — допустимо, запрос обрабатывается.

## Фича B — ошибка зависимости (REL-1)

1. LLM не ответил за 10 секунд → HTTP 504 с телом `{"detail": "llm timeout"}`.
2. LLM бросил исключение → HTTP 502 с телом `{"detail": "llm unavailable"}`; текст исключения наружу не отдаётся.
3. Сценарии фичи A сохраняются.
