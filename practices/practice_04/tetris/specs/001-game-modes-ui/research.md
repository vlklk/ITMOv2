# Research: Режимы игры и всплывающие подписи — интерфейс

Phase 0 для [plan.md](plan.md). Неизвестных в Technical Context нет: правила игры закрыты контрактом [`specs/shared/game-modes-contract.md`](../shared/game-modes-contract.md) v1.0. Ниже — решения интерфейса, прежде всего по детерминизму сквозных проверок без зависимостей.

## R1. Детерминизм партии: параметры URL

- **Decision**: `src/ui.js` читает из `location.search` параметры проверок (полный список — [contracts/ui-test-hooks.md](contracts/ui-test-hooks.md)): `seed`, `mode`, `clock`, `gravity`, `storage`. Неизвестные и некорректные значения молча игнорируются (обычное поведение). `seed` используется для **каждой** партии страницы (и «Играть снова»), иначе — `Date.now()` как сейчас. `mode` только предвыбирает режим на стартовом экране; в `createGame` попадает только id из `MODES`, поэтому `RangeError` (контракт §2.7) не возникает.
- **Rationale**: логика детерминирована по seed (конституция I), значит одинаковый seed даёт одинаковые фигуры в iframe и в планировщике. Параметры — внешний вход UI, без глобальных переменных и без изменения логики.
- **Alternatives considered**: глобальный объект `window.__tetris` для управления из теста — отклонён: тест должен проверять настоящий интерфейс через ввод и DOM, а не внутреннее состояние; подмена `Date.now` из родительской страницы — ненадёжна (модульный скрипт iframe выполняется раньше, чем родитель успевает вмешаться).

## R2. Время: ручные часы `clock=manual`

- **Decision**: в `src/ui.js` один источник времени интерфейса — «часы» с операциями «сейчас», «через N мс выполнить», «отменить». В обычном режиме — `performance.now`, `setTimeout`, `requestAnimationFrame`. При `clock=manual` кадров `requestAnimationFrame` нет: время двигается только событием `window` `tetris:advance` с `detail.ms`; обработчик режет `ms` на куски ≤ 1000 и для каждого выполняет тот же шаг кадра, затем срабатывают отложенные действия, чьё время наступило. Через эти часы идут все таймеры UI: гравитация, `advanceTime`, скрытие подписи (1,5 с), финальная подпись (~1 с), защита перезапуска (0,7 с), повтор кнопок касания.
- **Rationale**: ультра длится 120 с — ждать в реальном времени нельзя; время спринта становится точно известным (сумма переданных `ms`), что делает проверку «время на экране итога» точной. Гарантия контракта §2.3 сохраняется: `0 < deltaMs ≤ 1000`.
- **Alternatives considered**: ускорение времени (`timeScale`) — недетерминированно из-за реальных кадров; параметр «длина ультры» — меняет правило логики (запрещено: `timeLimitMs` — константа контракта).

## R3. Гравитация `gravity=off`

- **Decision**: при `gravity=off` цикл кадра вызывает `advanceTime`, но не `tick`. Фигуры движутся только клавишами.
- **Rationale**: планировщик моделирует только нажатия; без гравитации состояние iframe после каждого нажатия совпадает с состоянием планировщика. Цикл кадра — зона UI (контракт §2.3, шаг 3), правила не меняются.
- **Alternatives considered**: повторять в планировщике цикл кадра UI с накоплением `elapsed` — дублирует код UI и хрупко при смене уровня; двигать время только мелкими шагами меньше интервала падения — ломается с ростом уровня (A5 во всех режимах, Р-3).

## R4. Хранилище рекордов в проверках `storage=…`

- **Decision**: `storage=session` → `window.sessionStorage` (общий у раннера и iframe одного источника, переживает перезагрузку iframe, не трогает настоящие рекорды в `localStorage`); `storage=off` → `null` («хранилище недоступно»); `storage=readonly` → обёртка над `sessionStorage`, у которой `getItem` работает, а `setItem` бросает. Без параметра — `localStorageOf(window)` как сейчас. Раннер перед сценарием очищает ключи `tetris.record`, `tetris.record.sprint`, `tetris.record.ultra` в `sessionStorage` и при необходимости записывает исходные рекорды литералами.
- **Rationale**: проверки US2 должны задавать исходный рекорд и проверять перезагрузку, не портя рекорды игрока; ключи — из контракта §2.6. Выбор хранилища — побочный эффект окна, поэтому в `src/ui.js` (конституция I); `src/record.js` получает хранилище параметром.
- **Alternatives considered**: настоящий `localStorage` с резервной копией — риск потерять рекорд игрока при падении проверки; хранилище в памяти — не переживает перезагрузку iframe.

## R5. Ввод из раннера

- **Decision**: клавиши — `new KeyboardEvent("keydown", { code, key, bubbles: true })` в `document` iframe (обработчик UI смотрит `event.code`); выбор режима ↑/↓ обрабатывает тот же обработчик `keydown` UI (не нативное поведение элементов), поэтому работает и с синтетическими событиями; кнопки — `element.click()`; кнопки касаний — `click()` (путь `detail === 0`, как клавиатурное нажатие). Потеря фокуса — `dispatchEvent(new Event("blur"))` на `window` iframe; скрытая вкладка — `Object.defineProperty(document, "hidden", { configurable: true, get: () => true })` и событие `visibilitychange`.
- **Rationale**: синтетические события не вызывают действий браузера по умолчанию (Enter на кнопке не превращается в `click`, Tab не двигает фокус) — поэтому нажатия кнопок идут через `click()`, а клавиатурная доступность проверяется вручную (quickstart).
- **Alternatives considered**: WebDriver / Playwright — запрещены конституцией IV (зависимости).

## R6. Планировщик ходов и выбор seed

- **Decision**: `tests/e2e/planner.js` импортирует `src/game.js` и для каждой фигуры перебирает повороты 0–3 и сдвиги −5…+5, применяя только публичные функции (`rotate`, `moveLeft`, `moveRight`, `hardDrop`), оценивает поле (высота, дыры, неровность, убранные строки; режим «колодец» — правый столбец оставляется под вертикальную I ради тетриса) и выбирает лучший ход. Выход: список ходов (клавиши `ArrowUp`×r, `ArrowLeft`/`ArrowRight`×|dx|, `Space`), события каждого хода из `state.events`, число фигур до цели. Функция `findSeed(mode, predicate, range)` ищет seed, на котором план даёт нужное (финиш спринта за ≤ 150 фигур; событие `tetris`; событие `combo` с `n = 2`). Найденный seed записывается в сценарий литералом; сценарий перед запуском перепроверяет план и при расхождении даёт FAIL с пояснением.
- **Rationale**: собрать 40 строк одними клавишами без «зашитой» раскладки можно только планированием; планировщик опирается только на API контракта, поэтому проверяет UI, а не дублирует правила.
- **Alternatives considered**: подкладывать в UI готовое поле «38 строк» — UI создавал бы состояние в обход `createGame` (правила в UI, нарушение принципа I); граничное состояние допускалось ведущим как запасной путь — остаётся запасным: если для спринта seed не найден за 1…500, сценарий E2 проверяет финиш на поиске по большему диапазону и отмечает это в подробностях.

## R7. Раннер и запуск

- **Decision**: `tests/e2e/index.html` — статическая страница с кнопкой «Запустить все», списком сценариев (можно запустить один), таблицей «ID — сценарий — PASS/FAIL — подробности», итогом «N из M PASS» и `document.title` `e2e: PASS` / `e2e: FAIL`. Ошибки страницы iframe собираются слушателем `error` / `unhandledrejection` на `window` iframe; любая ошибка — FAIL сценария. Каждый сценарий получает новый iframe. Ожидания — опрос условия по реальному времени с таймаутом 3 с. Запуск: `python3 -m http.server 5173` → `http://localhost:5173/tests/e2e/index.html`; агент — MCP встроенного браузера (`preview_start` с `name: "tetris"`), `get_page_text` / `read_page` и `read_console_messages`.
- **Rationale**: без зависимостей (конституция IV); итог читается и человеком, и агентом.
- **Alternatives considered**: запуск в `node --test` — в Node нет DOM без библиотек; добавление в `scripts/check.sh` — запрещено без поручения.

## R8. Форматирование времени — `src/format.js`

- **Decision**: чистые функции: `formatSprintTime(ms)` — «м:сс,сс», от часа «ч:мм:сс,сс», сотые отбрасываются (`floor`); `formatUltraTime(ms)` — при `ms ≥ 10000` «м:сс», секунды `ceil` (120000 → «2:00», 10001 → «0:11», 10000 → «0:10»); при `0 < ms < 10000` — «0:0с,д», десятые `ceil` (9401 → «0:09,5», 1 → «0:00,1»); при `ms === 0` — «0:00»: ноль показывается только в момент конца; `formatScore(n)` — `Intl.NumberFormat("ru-RU")`. Разработка по TDD в `tests/format.test.js`, ожидания — литералы.
- **Rationale**: точность SC-003 и правила округления Р-8 проверяются в node без браузера; в `src/ui.js` (с DOM на импорте) их не протестировать.
- **Alternatives considered**: форматирование в `src/game.js` — это не правило игры, а показ; в `src/ui.js` — без unit-тестов.

## R9. Игровой цикл и состояния экрана

- **Decision**: состояния `start → playing ⇄ paused → finishing → over`, плюс `paused → start` («К выбору режима»). Кадр в `playing`: `deltaMs = min(now − last, 1000)` → `advanceTime` → шаги `tick` по `dropInterval(state.level)` (если гравитация включена) → после каждого вызова, если объект новый: показать события, обновить колонку, при `over` — `finish()`. После `paused` первая дельта не передаётся (контракт §2.3, шаг 5) — и при реальных, и при ручных часах, поэтому сценарий E5 видит одинаковое поведение. Пауза — по P/Esc, кнопке, `blur` и `visibilitychange` при `document.hidden`. При `over`: если `result !== null` — один `saveModeRecord`; при `sprintFinish`/`timeUp` — состояние `finishing` с финальной подписью ~1 с, затем `over`; при `topOut` — сразу `over`. Текущее состояние экрана отражается в `document.documentElement.dataset.screen`.
- **Rationale**: ровно последовательность контракта §2.3; одно место решения «когда звать логику»; атрибут — устойчивый хук для проверок и для CSS.
- **Alternatives considered**: подписи и финальная подпись через CSS-анимации с `animationend` — зависят от `prefers-reduced-motion` и не управляются ручными часами.

## R10. Подписи

- **Decision**: один слой `#caption` поверх поля, `pointer-events: none`, без фокуса. Источник — только `state.events` нового объекта. Текст: `tetris` → «Тетрис!», `backToBack` → «Подряд», `combo` → «Комбо ×n», `levelUp` → «Уровень n», `sprintFinish` → «Финиш!», `timeUp` → «Время вышло»; бонус > 0 — строкой «+N». Если в событиях есть финальное — показывается только оно. Новая группа заменяет старую; скрытие через 1,5 с по часам UI; на паузе и в `over` — скрыта. Озвучка — отдельный скрытый визуально `#announcer` (`aria-live="polite"`) получает текст группы одной строкой. Место — нижняя половина поля (не строки появления фигур и не колонка); точная раскладка — `docs/design-plan.md`.
- **Rationale**: FR-017–FR-026; события не выводятся из `combo`/`backToBack` самим UI (Р-26).
- **Alternatives considered**: очередь подписей по одной — противоречит FR-019; подписи в колонке — колонка заполнена (FR-006).

## R11. Колонка и стартовый экран

- **Decision**: колонка: строка `#time-stat` (в спринте и ультре) занимает место строки уровня; `#level-stat` скрыт в спринте и ультре; `#lines` в спринте — «min(lines, 40) из 40» (`linesToGoal` контракта для проверки цели). Последние 10 с ультры — атрибут `data-urgent` (красная ручка). Объявления диктору — в `#announcer` при `remainingMs`, впервые ≤ 60 000, 30 000, 10 000. Стартовый экран: список кнопок `[data-mode]` в порядке `MODES` с `aria-pressed`, названием, целью (числа из `goalLines`/`timeLimitMs`) и строкой рекорда; ↑/↓ меняют выбор, кнопка «Начать игру» стартует выбранный режим, клик по режиму выбирает его, повторный клик/Enter по выбранному стартует.
- **Rationale**: FR-001–FR-011; ≤ 4 значений помещаются в 20 клеток высоты.
- **Alternatives considered**: нативные `radio` — синтетические стрелки их не переключают (R5), а поведение стрелок разнится в браузерах.

## R12. Рекорды

- **Decision**: стартовый экран и колонка читают `readModeRecord(storage, id)`: `null` — строки нет, `0` — «рекорда пока нет», `> 0` — `formatScore` или `formatSprintTime`. При конце партии — `saveModeRecord(storage, mode, result)` один раз, если `result !== null`; пометка «Это новый рекорд.» при `isNew && previous > 0`; на итоге спринта «лучшее: …» — из `record`. Сам UI результат с рекордом не сравнивает (Р-16).
- **Rationale**: контракт §2.6; прежний рекорд марафона лежит в старом ключе — миграции нет.
- **Alternatives considered**: держать копию рекордов в UI — расходится с хранилищем при сбое записи (Р-17).
