# Контракт UI для сквозных проверок

Владелец — команда UI. Потребитель — `tests/e2e/`. Без параметров URL игра ведёт себя как обычно (B4); параметры не открывают ничего, кроме детерминизма.

## 1. Параметры URL `index.html`

| Параметр | Значения | Действие | Неверное значение |
|---|---|---|---|
| `seed` | целое (`/^-?\d+$/`) | seed для `createGame` во всех партиях страницы, включая «Играть снова» | игнор, `Date.now()` |
| `mode` | `marathon` \| `sprint` \| `ultra` (id из `MODES`) | режим выбран на стартовом экране; партия сама не стартует | игнор, «Марафон» |
| `clock` | `manual` | нет `requestAnimationFrame`; время UI идёт только по событию `tetris:advance` (§2) | игнор, реальное время |
| `gravity` | `off` | цикл кадра не вызывает `tick`; `advanceTime` вызывается | игнор, гравитация есть |
| `storage` | `session` \| `off` \| `readonly` | хранилище рекордов: `sessionStorage` / `null` / `sessionStorage`, у которого `setItem` бросает | игнор, `localStorageOf(window)` |

## 2. Событие времени

```text
window.dispatchEvent(new CustomEvent("tetris:advance", { detail: { ms: <число > 0> } }))
```

- Действует только при `clock=manual`; иначе игнорируется.
- `ms` режется на куски ≤ 1000; для каждого куска: часы UI += кусок → шаг кадра (в `playing`: `advanceTime(state, кусок)`, затем гравитация, если включена) → срабатывают отложенные действия UI, чьё время наступило (скрытие подписи, конец финальной подписи, защита 0,7 с).
- Правило контракта §2.3 шаг 5 действует и здесь: первый кусок после продолжения из паузы в логику не передаётся (часы UI при этом идут).
- Обработка синхронная: после `dispatchEvent` DOM уже обновлён.

## 3. DOM-хуки

Существующие id (`board-wrap`, `board`, `next`, `hold`, `score`, `level`, `lines`, `record`, `record-stat`, `screen-start`, `screen-pause`, `screen-over`, `start-button`, `resume-button`, `again-button`, `over-title`, `over-summary`) сохраняются.

| Хук | Где | Что проверяют |
|---|---|---|
| `html[data-screen]` | корень | `start` \| `playing` \| `paused` \| `finishing` \| `over` |
| `#mode-list [data-mode="<id>"]` | стартовый экран | порядок = `MODES`; выбранный — `aria-pressed="true"` |
| `[data-mode="<id>"] [data-record]` | стартовый экран | текст рекорда; элемента нет при недоступном хранилище |
| `#time-stat`, `#time` | колонка | есть в спринте и ультре; `#time[data-urgent]` — последние 10 с ультры |
| `#level-stat` | колонка | скрыт в спринте и ультре |
| `#lines` | колонка | в спринте — «N из 40» |
| `#caption` | поверх поля | видимость, строки `.caption-line`, `data-final` у финальной |
| `#announcer` | визуально скрыт | `aria-live="polite"`, текст последней группы / объявления времени |
| `#pause-time` | экран паузы | время режима (в спринте и ультре) |
| `#menu-button` | экран паузы | «К выбору режима» |
| `#over-title`, `#over-summary`, `#over-mark` | экран итога | заголовок по исходу, итог, пометка «Это новый рекорд.» |
| `#modes-button` | экран итога | «Выбрать режим» |
| `.cell[data-p]`, `.cell[data-g]` | поле | фигуры и призрак (как сейчас) |

«Видим» = элемент и предки без `hidden`, `getClientRects().length > 0`.

## 4. Клавиши

Обработчик `keydown` на `document` смотрит `event.code` (как сейчас) и на стартовом экране дополнительно `ArrowUp` / `ArrowDown` — смена выбранного режима. Синтетические события поддерживаются; нативные действия (Enter → click, Tab) раннер не эмулирует.
