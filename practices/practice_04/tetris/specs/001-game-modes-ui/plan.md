## Summary

Интерфейс трёх режимов («Марафон», «Спринт 40», «Ультра 2 минуты»), рекордов по режимам и всплывающих подписей событий поверх существующего интерфейса «тетрадь в клетку». Вся логика режимов, событий, бонусов и рекордов приходит от фичи 002 строго через API контракта [`specs/shared/game-modes-contract.md`](../shared/game-modes-contract.md) §2: `MODES`, `createGame(seed, modeId)`, `advanceTime`, поля состояния (`elapsedMs`, `remainingMs`, `linesToGoal`, `outcome`, `over`, `result`, `events`), `readModeRecord` / `saveModeRecord`. Интерфейс только рисует, меряет реальное время, передаёт `deltaMs` и решает, когда что показывать.

Технический подход:
- `index.html` — список режимов на стартовом экране, строка времени в колонке, слой подписей, новые кнопки экранов паузы и итога.
- `src/ui.js` — новый игровой цикл по контракту §2.3 (сначала `advanceTime`, потом гравитация), экраны `start → playing ⇄ paused → finishing → over`, подписи из `state.events`, рекорды по режимам, пауза и при скрытии вкладки.
- `src/format.js` — новый чистый модуль форматирования времени (без DOM), разрабатывается по TDD (`tests/format.test.js`).
- **Сквозные проверки без зависимостей**: страница `tests/e2e/index.html` открывает настоящий `index.html` в iframe с детерминированными параметрами URL (`?seed=…&mode=…&clock=manual&gravity=off&storage=…`), шлёт клавиатурные события, двигает время событием `tetris:advance`, проверяет видимое состояние DOM и выводит PASS/FAIL по каждому сценарию (E0…E17).

Реализация UI начинается **после** того, как логика 002 влита и `sh scripts/check.sh` проходит; UI использует только API контракта §2.

## Technical Context

**Language/Version**: JavaScript (ES2022, ES-модули) в браузере и Node.js ≥ 18 для `node --test`; HTML5, CSS (custom properties, `color-mix`, `round()` — уже используются)

**Primary Dependencies**: нет (конституция IV). Веб-шрифты Google Fonts — как сейчас

**Storage**: Web Storage через `src/record.js` (`readModeRecord` / `saveModeRecord`, ключи — контракт §2.6). Для сквозных проверок интерфейс по параметру URL берёт `sessionStorage`, `null` или обёртку, у которой запись бросает (research R4)

**Testing**: `node:test` + `node:assert/strict` (`sh scripts/check.sh`) — для `src/format.js` и потребительской проверки контракта; сквозные проверки — страница `tests/e2e/index.html` в браузере (MCP встроенного браузера), без библиотек

**Target Platform**: современные браузеры (Chromium, Firefox, Safari последних версий), десктоп с клавиатурой и телефон с касаниями, от 360 px ширины

**Project Type**: статическое веб-приложение без сборки (одна страница)

**Performance Goals**: 60 кадров/с без пропусков на поле 10×20; время в колонке обновляется не реже 10 раз в секунду (FR-007); подписи не вызывают перестройку раскладки

**Constraints**: без зависимостей и сборки; таймеры, DOM и хранилище браузера только в `src/ui.js`; правил игры в UI нет; ≤ 4 значений в колонке (FR-006); подписи не перехватывают ввод (FR-021); `prefers-reduced-motion` (FR-025, A9); существующие сценарии A/B не ломаются (B4)

**Scale/Scope**: 3 режима, 5 состояний экрана, 6 видов подписей, 4 истории; 18 сквозных сценариев; изменения в 3 существующих файлах интерфейса + 1 новый модуль + каталог `tests/e2e/`

Неизвестных (NEEDS CLARIFICATION) нет: правила закрыты контрактом v1.0, решения по детерминизму сквозных проверок — в [research.md](research.md).

## Сквозные проверки (обязательная часть)

Подробно — [research.md](research.md) R1–R7, хуки — [contracts/ui-test-hooks.md](contracts/ui-test-hooks.md), запуск — [quickstart.md](quickstart.md).

**Как это устроено**

1. `tests/e2e/index.html` (тот же источник `http://localhost:5173`) создаёт iframe с `../../index.html?<параметры>`.
2. Параметры URL — решение UI ради детерминизма; без них игра работает как обычно:
   - `seed=<целое>` — seed для `createGame` во всех партиях страницы;
   - `mode=marathon|sprint|ultra` — выбранный режим на стартовом экране;
   - `clock=manual` — время и все таймеры UI (подписи, финальная подпись, защита 0,7 с) идут только по событию `tetris:advance`;
   - `gravity=off` — UI не вызывает `tick` (время в логику передаётся);
   - `storage=session|off|readonly` — хранилище рекордов: `sessionStorage` / недоступно / запись бросает.
3. Харнесс шлёт `keydown` с `code` в `document` iframe; кнопки нажимает `.click()`; время двигает `CustomEvent("tetris:advance", { detail: { ms } })`; потерю фокуса — событием `blur`; скрытие вкладки — подменой `document.hidden` и событием `visibilitychange`.
4. Проверяет только видимое состояние: `document.documentElement.dataset.screen`, текст и видимость элементов по id из `contracts/ui-test-hooks.md`, клетки поля `[data-p]` / `[data-g]`.
5. Для спринта до финиша, «Тетрис!», «Комбо ×2», «Подряд» и «Уровень N» нужен seed с нужной партией. Планировщик `tests/e2e/planner.js` (только публичный API `src/game.js`) один раз при реализации T013 ищет seed; найденные seed, номер хода, N, бонус, очки и время записываются **литералами** в `tests/e2e/scenarios/fixtures.js` (конституция II). Во время прогона планировщик только превращает seed в клавиши; ожиданий он не даёт. До реализации значения — «TBD: найти при реализации T013».
6. Итог: таблица «сценарий — PASS/FAIL — подробности», строка «N из M PASS», `document.title` = `e2e: PASS` или `e2e: FAIL` (удобно читать через MCP).
