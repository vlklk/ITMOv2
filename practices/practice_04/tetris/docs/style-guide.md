# Style guide

1. Вся игровая логика — в `src/game.js`: чистые функции над обычным объектом состояния, без DOM, таймеров и `Math.random` внутри (случайность — через переданный seed). Побочные эффекты хранилища (рекорд в `localStorage`) — только в `src/record.js`: хранилище передаётся параметром, сбои хранилища не бросаются наружу. DOM, клавиатура, таймеры и получение `window.localStorage` — только в `src/ui.js`.
2. Тесты проверяют публичные функции `src/game.js` и `src/record.js`; функции `src/record.js` тестируются с подменой хранилища — объектом с интерфейсом Web Storage (`getItem`/`setItem`), в том числе бросающим ошибки. Ожидаемые значения — литералы, посчитанные вручную, а не вычисленные тем же кодом (`writing-good-tests.md` из skill TDD). В имени теста — ID требования: `A4: две строки за раз дают 300 × уровень`.
3. Без зависимостей, сборщиков и фреймворков: ES-модули, `node --test`, статический HTML/CSS.
4. Цвета, размеры клетки и шрифты — CSS-переменные в `:root` файла `src/styles.css`; в остальном CSS — только ссылки на них.
5. Не ослабляй `scripts/check.sh` и не удаляй тесты ради зелёного результата.

Хороший пример теста — `tests/smoke.test.js` по форме: `node:test` + `node:assert/strict`, одно поведение на тест.
