## 2. Контракт

Интерфейс логики (`src/game.js`) и рекорда (`src/record.js`), обязательный для обеих команд. Описано, что обещано наружу, а не как это сделано.

### 2.1 Режимы

Константа `MODES` — неизменяемый массив в постоянном порядке (LG FR-044, UI FR-001):

| `id` | Название (текст UI) | `goalLines` | `timeLimitMs` | `resultKind` | `better` | Конец партии |
|---|---|---|---|---|---|---|
| `marathon` | «Марафон» | `null` | `null` | `"score"` | `"higher"` | только переполнение |
| `sprint` | «Спринт 40» | `40` | `null` | `"time"` | `"lower"` | 40+ линий (финиш) или переполнение |
| `ultra` | «Ультра 2 минуты» | `null` | `120000` | `"score"` | `"higher"` | 120 000 мс игрового времени или переполнение |

- Режим по умолчанию — `marathon`; режим не меняется до конца партии (LG FR-002).
- Во всех режимах действуют A1–A6 и B1–B2; уровень и интервал падения растут по A5 во всех режимах, включая спринт и ультру (Р-3).
- Названия и цели — тексты UI; числа в них UI берёт из `goalLines` и `timeLimitMs` (Р-6).
- Порядок `MODES` = порядок режимов на стартовом экране.

### 2.2 Состояние партии, видимое UI

Существующие поля (`board`, `active`, `next`, `hold`, `holdUsed`, `bag`, `rng`) сохраняются без изменения смысла. Добавляются или уточняются:

| Поле | Тип | Единицы | Когда меняется |
|---|---|---|---|
| `mode` | `"marathon" \| "sprint" \| "ultra"` | — | задаётся в `createGame`, далее постоянно |
| `score` | целое ≥ 0 | очки | при спуске (A3), фиксации (A4) и бонусах; когда UI видит событие с бонусом, `score` его уже включает |
| `lines` | целое ≥ 0 | строки, фактические (может быть 42) | при фиксации со строками (Р-10) |
| `level` | целое ≥ 1 | — | при фиксации, по A5, во всех режимах (Р-3) |
| `linesToGoal` | целое ≥ 0 или `null` | строки | спринт: `max(0, 40 − lines)`; иначе `null`. UI показывает «min(lines, 40) из 40» (Р-10) |
| `elapsedMs` | число ≥ 0, может быть дробным | мс игрового времени | только в `advanceTime`; во всех режимах; в ультре не больше 120 000 (Р-7, Р-8) |
| `remainingMs` | число ≥ 0 или `null` | мс | ультра: `max(0, 120000 − elapsedMs)`; иначе `null` |
| `outcome` | `"playing" \| "topOut" \| "sprintFinish" \| "timeUp"` | — | один раз, при конце партии (§2.5) |
| `over` | `boolean` | — | `true` ровно тогда, когда `outcome !== "playing"` (Р-13) |
| `result` | целое ≥ 0 или `null` | очки или мс (по `resultKind`) | `null`, пока идёт партия; при конце — по §2.5 (Р-14) |
| `combo` | целое ≥ 0 | длина серии | при каждой фиксации: +1, если убраны строки; 0, если нет. Hold, сдвиги и повороты не меняют |
| `backToBack` | `boolean` | — | `true`, если последняя фиксация **со строками** была тетрисом; фиксация без строк значение не меняет; фиксация с 1–3 строками сбрасывает в `false` (Р-4) |
| `events` | `Event[]` | — | события **этого** вызова; `[]` в любом новом объекте без событий (Р-5, §2.4) |

**Правило объекта** (Р-5, Р-20, Р-24):
1. Вызов, который ничего не изменил (упор в стену, отменённый поворот, повторный hold, некорректное время, любой вызов после конца партии), возвращает **тот же объект** (`===` входу).
2. Любой новый объект содержит в `events` только события, порождённые этим вызовом.
3. UI читает `events` только тогда, когда результат вызова `!==` входу.

### 2.3 Функции

Все функции `src/game.js` — чистые: не изменяют вход, не читают часы, не используют `Math.random` (принцип I). Исключение бросает только `createGame` при нарушении контракта; остальные функции на неподходящий вход отвечают тем же объектом.

| Функция | Вход | Выход | Ошибки и граница |
|---|---|---|---|
| `createGame(seed, modeId = "marathon")` | `seed` — число; `modeId` — id из `MODES` | новое состояние: `outcome "playing"`, `over false`, `elapsedMs 0`, `combo 0`, `backToBack false`, `events []`, `result null` | неизвестный `modeId` → `RangeError`; `undefined` → марафон; с одним аргументом поведение как сейчас (B4) (Р-21) |
| `moveLeft`, `moveRight`, `rotate` | состояние | состояние | не фиксируют; `combo`, `backToBack` не меняются; событий нет |
| `hold` | состояние | состояние | B2; не фиксация — серия и цепочка не меняются; событий нет |
| `softDrop`, `tick` | состояние | состояние | при фиксации — события фиксации, возможны `sprintFinish` и `topOut` |
| `hardDrop` | состояние | состояние | всегда фиксирует (A3); события как у фиксации |
| `advanceTime(state, deltaMs)` | состояние; `deltaMs` — конечное число > 0 | состояние с `elapsedMs + deltaMs` (в ультре — не больше 120 000) | `deltaMs ≤ 0`, `NaN`, `±Infinity` или партия окончена → тот же объект. В ультре при достижении 120 000: `outcome "timeUp"`, `result = score`, падающая фигура не фиксируется, `events = [timeUp]` |
| `ghostPiece`, `dropInterval`, `lineClearPoints`, `levelForLines`, `pieceCells`, `spawnPiece` | как сейчас | как сейчас | без изменений |

**Последовательность вызовов (кто кому что передаёт и когда)** (Р-7, Р-9, Р-23):

1. Стартовый экран: UI строит список из `MODES` и для каждого режима вызывает `readModeRecord(storage, id)`.
2. Начало партии: UI → `createGame(Date.now(), modeId)`.
3. Каждый кадр, пока партия в состоянии «играем»: UI измеряет `deltaMs` и ограничивает его 1000 мс → **сначала** `advanceTime(state, deltaMs)`, **затем** шаги гравитации `tick` по `dropInterval(state.level)`. После каждого вызова UI сравнивает объект с прежним и при отличии читает `events`, `over` и поля колонки.
4. Нажатия между кадрами: UI → `moveLeft` / `moveRight` / `rotate` / `softDrop` / `hardDrop` / `hold`, после каждого — то же чтение. Нажатия время не передают.
5. Пауза (клавиша, кнопка, `blur`, `visibilitychange` со скрытием вкладки), финальная подпись, экраны начала и итога: UI не вызывает `advanceTime` и игровые функции. Первая дельта кадра после продолжения в игру не передаётся.
6. Конец партии (`over === true`): UI прекращает игровые вызовы, один раз вызывает `saveModeRecord(storage, mode, result)`, если `result !== null`, показывает финальную подпись (~1 с, UI FR-012) и затем экран итога.
7. «К выбору режима» с экрана паузы: UI отбрасывает состояние; логика и рекорд не вызываются (Р-13).

**Гарантии UI для логики**: `deltaMs` передаётся только в состоянии «играем»; `0 < deltaMs ≤ 1000`; время паузы и скрытой вкладки не передаётся.

### 2.4 События

Тип `Event = { type, bonus, ...параметры }`; `bonus` есть у всех событий, 0 — если бонуса нет (Р-11).

| `type` | Параметры | `bonus` | Когда | Текст UI |
|---|---|---|---|---|
| `tetris` | — | 0 | фиксация убрала 4 строки | «Тетрис!» |
| `backToBack` | — | 400 × уровень до фиксации | тетрис, если предыдущая фиксация **со строками** — тоже тетрис; фиксации без строк между ними не мешают (Р-4) | «Подряд» |
| `combo` | `n` — длина серии, ≥ 2 | 50 × (n − 1) × уровень до фиксации | фиксация со строками, после которой серия ≥ 2; первое такое событие — `n = 2` (Р-2) | «Комбо ×N» |
| `levelUp` | `level` — новый уровень | 0 | фиксация подняла уровень по A5, в любом режиме (Р-3) | «Уровень N» |
| `sprintFinish` | `timeMs` — целые мс (= `result`) | 0 | фиксация довела линии спринта до ≥ 40 | «Финиш!» |
| `timeUp` | `score` — итоговые очки (= `result`) | 0 | `advanceTime` довёл время ультры до 120 000 мс | «Время вышло» |

- **Порядок** внутри `events`: `tetris`, `backToBack`, `combo`, `levelUp`, затем не больше одного финального события (`sprintFinish` или `timeUp`) — всегда последним (Р-12).
- **Способ выдачи**: поле `events` объекта, который вернул вызов; только события этого вызова; повторно не выдаются; новая партия начинается с `events = []` (Р-5).
- `timeUp` приходит только из `advanceTime`; `sprintFinish` — только из вызова с фиксацией (`tick`, `softDrop`, `hardDrop`).
- Если в `events` есть финальное событие, UI показывает только его подпись (UI FR-020).
- Сумма `bonus` событий вызова = прибавка `score` сверх очков за строки (A4) и спуск (A3). Бонусы считаются по уровню до фиксации.

### 2.5 Исходы партии

| `outcome` | Режимы | Условие | `result` | Экран итога (UI) |
|---|---|---|---|---|
| `playing` | все | партия идёт | `null` | — |
| `topOut` | все | новая фигура не помещается в точку появления (A6) | марафон и ультра — `score`; спринт — `null` | «Игра окончена». Марафон: очки и строки. Спринт: «собрано N из 40 строк», «время не засчитано». Ультра: очки и строки, результат идёт в рекорд (Р-1) |
| `sprintFinish` | спринт | после фиксации `lines ≥ 40`; важнее переполнения той же фиксацией (Р-22) | `Math.round(elapsedMs)` | «Финиш», время партии, лучшее время |
| `timeUp` | ультра | `elapsedMs` достиг 120 000 | `score` | «Время вышло», очки и строки |

После любого исхода, кроме `playing`, все функции возвращают тот же объект (LG FR-010, UI L-7). Если при `sprintFinish` новая фигура стоит поверх занятых клеток, UI рисует её, как сейчас после проигрыша, без призрака.

### 2.6 Рекорды по режимам (`src/record.js`)

**Ключи хранения** (Р-18):

| Режим | Ключ | Значение |
|---|---|---|
| `marathon` | `tetris.record` (прежний ключ) | целые очки > 0 |
| `sprint` | `tetris.record.sprint` | целые мс > 0 |
| `ultra` | `tetris.record.ultra` | целые очки > 0 |

**Миграция**: не нужна. Рекорд, сохранённый до фичи, уже лежит в ключе марафона и читается как рекорд «Марафона» (UI FR-028, LG FR-031). У спринта и ультры при первом запуске рекорда нет.

**Значение рекорда**, одинаковое для всех режимов (Р-15):
- `null` — хранилища нет или из него нельзя читать; UI не показывает строк рекорда ни на одном экране;
- `0` — рекорда нет («рекорда пока нет»); испорченное значение (не число, не целое, ≤ 0) тоже читается как `0`;
- `> 0` — рекорд.

| Функция | Вход | Выход | Ошибки |
|---|---|---|---|
| `localStorageOf(win)` | окно | хранилище или `null` | как сейчас, не бросает |
| `readModeRecord(storage, modeId)` | хранилище или `null`; id из `MODES` | `null \| 0 \| целое > 0` | сбои хранилища не бросает; неизвестный `modeId` → `RangeError` |
| `saveModeRecord(storage, modeId, result)` | хранилище или `null`; id; `result` — целое ≥ 0 | `null`, если хранилище недоступно для чтения; иначе `{ record, previous, isNew }` | сбои хранилища не бросает; неизвестный `modeId` → `RangeError`; при сбое записи `record = previous`, `isNew = false` (Р-17) |
| `readRecord(storage)`, `saveRecord(storage, score)` | как сейчас | как сейчас | остаются как функции марафона; тесты B3 не меняются (Р-25) |

Поля итога сохранения: `record` — действующий рекорд после сохранения (`0`, если рекорда нет); `previous` — рекорд до сохранения (`0`, если его не было); `isNew` — результат записан как новый рекорд.

**Сравнение** (LG FR-032, UI FR-014): по `better` из `MODES`; новый рекорд — только если результат **строго** лучше действующего (`higher` — больше, `lower` — меньше). Если рекорда нет (`previous === 0`), рекордом становится любой положительный результат. `result === 0` рекордом не становится (Р-19). Равное время спринта — не рекорд. Проигранный спринт (`result === null`) не сохраняется. Сравнивает только `src/record.js`; UI направление не повторяет.

**Признак «побит»** (Р-16): пометка «Это новый рекорд.» показывается при `isNew && previous > 0`. В первой партии режима пометки нет, но рекорд записан.

**Недоступное хранилище** (UI FR-029, LG FR-034): все режимы играются от начала до итога; ни одна функция не бросает; UI не показывает строк рекорда и сообщений об ошибке.

### 2.7 Сводка ошибок и границ

| Ситуация | Сторона | Поведение |
|---|---|---|
| Неизвестный `modeId` в `createGame`, `readModeRecord`, `saveModeRecord` | логика, рекорд | `RangeError` — нарушение контракта; в рабочем UI не возникает (id только из `MODES`) |
| `modeId` не передан в `createGame` | логика | марафон |
| `deltaMs` ≤ 0, `NaN`, `±Infinity`; время после конца | логика | тот же объект, без исключения |
| Любое действие после конца партии | логика | тот же объект |
| Хранилища нет, чтение бросает | рекорд | `null`; UI без строк рекорда |
| Запись бросает (квота и т. п.) | рекорд | `record = previous`, `isNew = false`; UI без пометки |
| Испорченное значение в хранилище | рекорд | `0` — «рекорда нет» |
| Пауза, потеря фокуса, скрытая вкладка, финальная подпись | UI | время в логику не передаётся; `deltaMs ≤ 1000` |
